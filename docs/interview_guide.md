# 面试话术指南（interview_guide）

> 3 分钟讲清：动机 → 架构 → 实验 → 结论 → 下一步。每个数字都能复现、
> 每个结论都诚实（可承受追问）。本文是「讲什么」与「被问什么」的答案库。

## 一、3 分钟电梯陈述

**动机（30s）**：我在 tcms-can-test 上手写了 777 个 pytest 用例、语句覆盖率
98%。行业里「LLM 写测试」很热，但有个没人答的问题：**LLM 写的用例，怎么
证明它是好的？** 靠人看不行——要可复现的量化证据。所以我把「质量评估」
本身做成了工程流水线。

**架构（60s）**：三条关键决策。
1. **真实资产驱动**：解析真实 TCMS 的 DBC（8 报文/36 信号，含 VAL_ 枚举与
   周期属性）+ 13 个故障场景 YAML，作为生成输入——不是玩具。
2. **受约束 execution DSL 弥合鸿沟**：我 P2 实证过，LLM 生成的自由自然语言
   用例几乎无法编译成真实测试。解法是让生成器输出白名单内的机器可读执行
   意图（注入哪个故障/信号、断言什么），期望由 oracle（上游 faultlevel 语义
   镜像）派生，不手抄不编造。mock 与真实 LLM 走同一 DSL、同一管线，可比。
3. **真实执行 + 变异杀毒**：用例编译成真实 pytest 在上游平台跑，通过率是
   真的；再用「行为翻转」变异被测对象，看用例能不能杀死变异。

**实验（60s）**：两条硬证据。
- mock 生成 34 条 → 真实 pytest 34/34 过（compile 率 100%）。
- 我翻转了 3 个真实行为（车门故障被吞、编码不拒越界、超速处置被改），
  生成用例**全部杀死**（kill_rate 1.0）；而规则基线生成器对其中 2 个变异
  完全无感知——**只报通过率会误判「谁都会写测试」，变异覆盖才是质量标尺**。

**结论 + 下一步（30s）**：DSL 约束 + oracle 派生 + 真实执行 + 变异杀毒 = 一条
可复现的「AI 测试质量证据链」。下一步：接真实 LLM 做多模型对比（管线已就绪），
并量化生成集对 777 手写用例的组合增量。

## 二、追问应对（预演）

**Q1 这不是模板填空吗？生成的用例有什么智能？**
答：诚实拆解——「创作归系统，LLM 负责广度选择」。LLM 的价值在从资产里
选场景 × 组合故障键 × 处置动作 × 时序（10 故障键 × 模式 × recover 的笛卡尔
空间手写难穷举，这就是组合增量）。模板保证可执行，选择与组合才是生成。
另外我在实验里诚实暴露了 mock 下限——真 LLM 的增量 = 超出 mock 的部分。

**Q2 为什么用 DSL 不让 LLM 直接写代码？**
答：两个原因。一是安全——真实列车控制系统的测试不允许自由代码进执行器，
白名单原语是安全边界。二是可度量——自由代码无法结构化评估，DSL 让
parse/compile/kill_rate 都可计算。P2 数据支持：自由文本 compile≈0。

**Q3 kill_rate 怎么证明不是自证预言？**
答：变异是我对上游真实行为做的翻转（如 set_door_state 把 Fault 吞成
Closed），用例事先不知道。相关用例全被杀 = 用例断言真实覆盖该行为；
不相关用例 survive = 统计口径排除（relevant 分母）。规则基线对照证明
区分度：它 pass_rate 也 100%，但对 2/3 变异无感知。

**Q4 真实 LLM 跑过吗？**
答：诚实说——本机无 API key 环境时用 mock 与规则基线完成实验设计验证，
OpenAICompatClient 已就绪（同契约同管线），接 key 即补臂，不改变实验结构。
我不会把 mock 数字说成 LLM 质量。

**Q5 覆盖率 98% 的 777 例 vs 你的生成器，谁强？**
答：这不是替代关系。777 例是金标（human expert 上界），生成器是探索
「手写难穷举的组合维度」（故障 × 模式 × 时序）。组合增量量化是明确的
future work：对上游 rtm.csv 做集合差。
